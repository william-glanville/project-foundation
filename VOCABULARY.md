# Canonical Vocabulary

## Authority

Terms defined here are authoritative for this project after human review and acceptance. Alternate spellings, aliases, states, and abbreviations are prohibited unless explicitly listed.

## Rules

- Define one canonical name for each domain concept.
- Separate entity names, lifecycle states, review decisions, actions, and display labels.
- Record permitted aliases only for external compatibility.
- Record prohibited aliases that have caused or could cause drift.
- Do not infer new states from implementation or tests.
- Changes to accepted vocabulary require impact review across contracts, ADRs, schemas, prompts, code, tests, and documentation.
